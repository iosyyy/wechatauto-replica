## 改动与证据边界

- 可选 `fast_desktop_checks=true`：持续读取和发送检查仍实时核对账号目录、进程实例、
  映像、活动 FD、数据库页 HMAC 和固定可见窗口；界面会话、正文及焦点由发送器的
  新完整界面树校验，不使用账号校验 TTL 缓存。
- 可选 `desktop_layout.reuse_verified_controls=true`：仅用于 `set_value` 与
  `focused_return`。准备记录只允许消费一次，并绑定精确目标和正文哈希；最终慢校验
  回调之后仍重新读取完整树。发送确认仍依赖数据库的正数 `server_id`。
- 最近会话存在唯一对应行时直接打开，避免全局搜索把联系人与聊天记录列成同名结果。
  系统会话别名同时用于标题、输入框和等待选择器。
- `delivery_confirm_timeout` 默认 30 秒，只延长只读确认等待，不会二次输入或提交。
  普通私聊已出现“文字真实发出，但旧 8 秒窗口内尚未确认”的情况；之后按原请求哈希
  与实际数据库正文、正数 `server_id` 精确核对，未盲目重发。
- LangBot 配套补丁为只读登录状态和 profile GET 增加可取消的连接错误/超时退避重试。
  认证、JSON/schema 错误和生成授权的 POST 不重试。API 更新成功只表示已调度，
  不能代替 WebSocket 启动与真实问答验收。

## 群记录与插件

[NativeWeChatHistory](../integrations/langbot/native-history/README.md) 使用独立凭据与可信
会话身份：所有者私聊可以查询已授权的其他群；群内仅能查询当前群。群历史直接读取
本机已同步数据库，不依赖只缓存当前新消息的 GroupChatSummary。

`group_request_prefix="/lb "` 可让普通群消息只留在本地，明确提问才进入模型。
这与历史读取范围分离。群聊流水线不使用私人 PowerContext 绑定，避免私聊记忆带入群内。
当前原生文字流水线使用纯风格插件，保留原人设；图片工具留在原有已支持图片的通道。

真实部署已验证历史服务内网连通：所有者请求 HTTP 200，非所有者 HTTP 403。
此记录写入时机器人尚未加入目标群，本地群数为 0，真实群记录读取和群发送尚未验收。
入群前或未同步到这个账号的记录不能凭接口恢复。
